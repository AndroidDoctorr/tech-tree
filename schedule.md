## How to read dates *(no third calendar)*

Use **two tracks** only — already in every journal day file:

| Track | Example now | Use for |
|-------|-------------|---------|
| **Day N** | **562** | Absolute timeline · immortality counter · never resets |
| **Cal-Yn Dk** | **Cal-Y2 D325** | **Deadlines** · planting/harvest windows · feast countdown |

**Formula:** `Day N` → `Cal-Y2 D(N−237)` for N ≥ 238. **Feast eve** closes each full calendar year @ **Day 237 + 365×(Y−1)** → Cal-Y2 closes **Day 602** (= Cal-Y2 D365).

**Season phase** (spring sow · autumn harvest · madder root) keys off **SUN-CAL-1** marks and logged anchors — **not** Roman months or a fictional 13×28 grid. See [sun-calendar.md — Operational discipline](sun-calendar.md#operational-discipline).

### Why not a 13-month / 28-day year?

A third naming system (e.g. *Month 7, Day 14*) would:

- Duplicate what **Cal-Y D** already gives you — **days since last winter solstice feast**
- Require constant conversion (`Day 562` ↔ `Cal-Y2 D325` ↔ `Moon 11 Day 6`) with no gain in farm accuracy
- Fight the **SUN-MARK** figure-8, where “winter feels stuck” and spring legs run faster — real windows are **mark-triggered**, not neat 28-day months

**Verdict:** Keep **Day + Cal-Y D** for scheduling. Keep **SUN marks** for field gates. Revisit a display name (e.g. “Feast−40”) only if you want flavor — not a parallel canon.
